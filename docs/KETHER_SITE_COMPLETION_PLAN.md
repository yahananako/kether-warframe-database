# KETHER 全站補齊計畫

更新：2026-10-04（Asia/Taipei）
基準：main 的 3a0b282；此文件記錄程式盤點與實作狀態，不代表正式站已驗收。

## 目標與範圍

延續沉浸式首頁風格，統一共用介面，再按資料查詢、故事閱讀、即時情報、個人管理的用途調整內頁。首頁桌面維持滿版；長資料與故事可正常捲動。手機不依賴 hover。Android APP 維持暫停更新；既有網站與 BOT 權限不可因視覺修改放寬。

狀態定義：待盤點＝有路由但內容與行為尚未逐項驗收；待實作＝有明確待辦；本批完成＝程式已完成，仍以合併後正式站驗收為準。

## 已證實的缺口與本批修補

| 缺口 | 修補 | 狀態 |
| --- | --- | --- |
| 登入頁 session fetch 無逾時 | 8 秒取消查詢，顯示提示並允許重新登入；卸載取消請求 | 本批完成 |
| OAuth 錯誤直接顯示 JSON，取消授權缺少返回流程 | 統一返回登入頁，使用繁中原因提示並保留目的頁 | 本批完成 |
| OAuth token、profile、member 請求無期限 | 共用 15 秒訊號；網路、逾時與格式錯誤皆可重新登入 | 本批完成 |
| next 僅檢查前導斜線 | 共用安全目的頁函式；排除外站、反斜線、控制字元與登入/API 循環 | 本批完成 |
| 全域缺少載入、404、錯誤邊界 | 新增 loading、not-found、error、global-error 與共用 PageState | 本批完成 |
| 共用選單未標示目前頁 | 精確匹配目的路由，提供 aria-current 與可見外框 | 本批完成 |

既有權限規則、OAuth scopes、登入同意流程、聯盟成員支援、session 簽章與 cookie 保護不變。新失敗提示不展示 OAuth token、個人資料或原始例外。

## 共用介面剩餘工作

- [ ] 先建立一套內頁殼層：導覽、搜尋、鈴鐺、個人入口、麵包屑、頁尾。
- [ ] 以一個資料分類試用，再逐頁套用；不一次覆寫所有 CSS。
- [ ] 導覽鍵盤焦點、Escape、點擊外部關閉、手機觸控與桌面 hover 完整驗收。
- [ ] 浮動播放器切頁保留播放、手機縮小、不遮操作；背景動態可停用，尊重減少動畫設定。
- [ ] 統一狀態：載入、無結果、無權限、讀取失敗、過期與最後成功更新。
- [ ] 清除頁面中「保留原邏輯／只統一外層版型」等開發說明。
- [ ] Footer 統一網址、實際網站版本、更新說明與共同開發署名。
- [ ] 各頁正確 title/canonical；個人與管理頁 noindex；不得將私密頁列入 sitemap。

## 實作與交付順序

1. 第一批：本文件＋登入復原＋全域狀態，獨立 PR 驗證。
2. 第一階段續作：共用內頁殼層、未授權頁、手機導覽、播放器及動態偏好。
3. 第二階段：資料庫共用模板先行，武器／同伴／曲翼／MOD 逐分類套用，戰甲與靈化另驗專用功能。
4. 第三階段：故事目錄與閱讀模板，最後逐篇核對 32 篇與支線／系列內容。
5. 第四階段：電波局與時間處理、通知來源一致、氏族與 BOT 說明。
6. 第五階段：個人進度與編輯器、資料狀態、分享資訊與全站巡檢。

除共用底層修補外，以每週一個主題頁為規劃節奏，不代表已排定自動執行。每批記錄預覽、測試結果、已知限制與回復方式。網站版本延續 v2.x.x；合併前確認當時版本再遞增，避免與其他工作衝突。

## 驗收與發布門檻

- 本批自動化：`npm run test:auth-recovery`、`npm run test:discord-access`、`npm run build`。
- 全站內容修改時再按變動範圍執行資料驗證；靈化資料變更順序：`npm run data:incarnon` → `npm run data:android` → `npm run test:android-search` → `npm run build`。產生 Android 資料不等於發布 APP。
- 桌面至少 1440×900、使用者 16:10 筆電比例；手機至少 390×844；200% 放大不裁切操作。
- 登入驗收：正常、取消、state 過期／不符、網路逾時、缺少群組、缺少身分組；前端保留同意要求。
- 登入成功後回到原頁；任何 next 值不得跳到外站或登入／API 循環。
- OAuth 端點 mock 測試不能代替真實 Discord OAuth 端到端驗收。
- PR 預覽驗收後才合併正式站；未發布或未測的部分必須明確標示。
- 回復方式：撤回該批 commit；本批無資料庫結構變更。
